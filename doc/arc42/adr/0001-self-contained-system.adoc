= ADR 0001: Self-Contained System

== Status

Accepted (reflects the system as already implemented; recorded here for traceability, not proposing a change).

== Context

Pet Clinic needs HTTP API consumers that present the same domain data without duplicating business logic or owning their own data store.

== Decision

The system is built as a **Self-Contained System**: one backend server owns the database and all business logic, and exposes it through REST and GraphQL APIs.
API consumers are thin — they call the backend's APIs, holding no server-side logic or independent data of their own.

== Alternatives considered

- **Micro-frontends with per-client backends-for-frontend (BFF)** — rejected: adds an extra hop and duplicated data-shaping logic for a system this size.
- **Shared monolithic server-rendered UI** — rejected: a clean API boundary is required rather than server-side rendering coupling.

== Consequences

- Every consumer uses the same REST/GraphQL contract — defined once in `openspec/specs/backend/*`.
- The backend must keep its API contract stable and versionable independent of any one consumer's release cycle.
