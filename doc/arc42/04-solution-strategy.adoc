= 4. Solution Strategy

- **Self-Contained System** — one backend server owns the database and all business logic and exposes it through REST and GraphQL; browser clients are thin, holding no server-side logic or independent data of their own.
See xref:{relrootdir}/doc/arc42/adr/0001-self-contained-system.adoc[ADR 0001].
- **OpenSpec-driven client generation, in separate repositories** — every client is generated from the same normative contract (`openspec/specs/*`) rather than hand-copied between stacks, and lives in its own repository so "rebuild from scratch" has an unambiguous meaning.
See xref:{relrootdir}/doc/arc42/adr/0002-openspec-driven-client-generation.adoc[ADR 0002].
- **REST for commands and queries, GraphQL for queries only** — REST carries Spring Data REST's built-in ETag/pagination/filtering conventions for writes; GraphQL adds efficient nested reads on top of the same data.
See xref:{relrootdir}/doc/arc42/adr/0003-rest-and-graphql-duality.adoc[ADR 0003].
- **AI-agent-driven implementation, via reusable skills** — the system is implemented and maintained by AI agents rather than hand-coded per change; a skill (`.agents/skills/`) operationalizes the detailed patterns in `doc/concept` into a reproducible workflow — which guide to follow, which artifacts to create or update, how to validate the result with tests — so the same kind of change is done the same way every time, by any agent.
See xref:{relrootdir}/doc/arc42/adr/0004-ai-agent-driven-implementation.adoc[ADR 0004].
- **`openspec`, `obsidian`, and `doc/arc42` each own exactly one kind of fact, for documentation that doesn't drift** — `openspec` is the normative contract, `doc/arc42` is the bird's-eye and architecture reference, and `obsidian` is the explanatory knowledge graph; a defined precedence between them, plus the rule that an Obsidian note is a hypothesis about the code and never an independent fact, is what keeps this many documentation artifacts from silently disagreeing as the system evolves.
See xref:{relrootdir}/doc/arc42/adr/0005-documentation-split-and-precedence-order.adoc[ADR 0005].
