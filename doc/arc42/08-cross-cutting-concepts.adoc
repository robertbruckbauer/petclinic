= 8. Cross-cutting Concepts

Each concept is normatively defined in implementation guids in `doc/concept` and explained in the knowledge graph in `obsidian` for better understanding and traceability.

== CQRS Style REST/GraphQL Split

Reads and writes travel separate paths: REST carries both commands and queries per entity, while GraphQL offers read-only queries for flexible client-side data shaping.

== Optimistic Concurrency

Every entity carries a version-derived ETag, and mutating requests must present it, so a stale write is rejected instead of silently overwriting a concurrent change.

== Pagination and Filtering

Collection endpoints are paginated, sorted, and filterable by query parameter, keeping large result sets bounded and searchable without bespoke per-entity logic.

== Logging

All logging goes through one SLF4J facade and one shared entity-lifecycle base class, giving every entity the same uniform, secret-free log output, with verbosity fixed by configuration rather than adjustable at runtime.

== Monitoring

The running application's identity and health are exposed as plain, unauthenticated HTTP endpoints (version, liveness, readiness), independent of the deeper business functionality.
